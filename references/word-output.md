# Word默认交付

本包可独立生成并检查 Word；已有 docx 技能时可配合使用，不作为强制前置。首次使用先读[环境与迁移说明](portability.md)。字体采用用户指定规范；当前模板A4纵向、四边约２厘米。不要擅自缩小表格字来压页数。

| 层级 | 字体字号与格式 |
|---|---|
| 标题 | 方正小标宋简体，小二，１８磅，不加粗，居中 |
| 一级 | 黑体，三号，１６磅，不加粗；一、至六、 |
| 二级 | 楷体_GB2312，三号，加粗；（一）（二）等 |
| 三级 | 仿宋_GB2312，三号，加粗；如“1.整理想法”，点号后不加空格或制表符，数字同字体；最多三级 |
| 正文 | 仿宋_GB2312，三号，不加粗，两端对齐，首行缩进两字符 |

一级、二级、三级标题均首行缩进两个字符；正文同样首行缩进两个字符。总标题居中，不设首行缩进。

辅助表格首行表头与左栏项目小标题水平居中、垂直居中，无首行缩进；其余内容正文两端对齐、首行缩进两个字符。课程脉络是独立的横向阶段表：一行四格、顶端对齐，阶段名居中，活动名称左对齐且无首行缩进；保留原稿浅蓝、浅绿、浅橙、浅粉的四格区分。

所有段落段前段后０磅、固定行距２８磅。正文标点采用中文格式且使用正文字体。三级标题按用户明确要求保留阿拉伯数字加点；网址本身保持有效，不替换网址标点。表格正文同字号与行距；辅助表可为二列或三列，重复表头且不拆短行。脉络格内只写简短阶段与活动名，详细过程放正文，不缩小字塞进四格。

## 信息组织与阅读层次

文末“资料依据与设计借鉴”使用现有二级标题样式，不新增第七个一级部分。具体分组和溯源边界见 [来源规范](source-guide.md)；类别名作为段首提示，如“年龄依据：”“案例借鉴：”，每类独立正文段落，同类多项重要来源可分段。不能把数项案例、年龄依据和技术说明塞进一个长段落，也不靠连续空格、软换行、空白段或缩小字号制造层次。

课程脉络表后可有一两句推进说明，只解释阶段如何衔接；没有新增信息时省略，不重复逐项介绍表格。不要强制加过渡段，也不要为了压页数删除必要的来源或改编说明。

## 生成脚本

```text
node scripts/build_word.cjs 输入.json 输出.docx
python scripts/check_word.py 输出.docx --out 核查目录
```

JSON结构：
```json
{
  "title": "社会主义核心价值观自由主题课程",
  "sections": [
    {
      "title": "一、课程缘起",
      "blocks": [
        {"text": "正文。"},
        {"text": "从具体场景与儿童问题说明课程如何产生。"}
      ]
    },
    {"title": "二、课程目标", "blocks": [{"text": "在具体活动中尝试表达、行动与理解。"}]},
    {"title": "三、课程脉络", "blocks": [{"roadmap": [
      {"title": "发现问题", "activities": ["整理想法"]},
      {"title": "尝试办法", "activities": ["比较做法"]},
      {"title": "实际行动", "activities": ["试一试"]},
      {"title": "回看调整", "activities": ["再试一次"]}
    ]}]},
    {"title": "四、课程实施", "blocks": [
      {"level": 2, "text": "（一）发现问题"},
      {"level": 3, "text": "1.整理想法"},
      {"text": "此处是输入格式示意；完整课程须展开脉络中的全部活动。"},
      {"table": [["活动环节", "观察重点", "教师支持"], ["表达", "是否说出愿望", "提供图片选择"]]}
    ]},
    {"title": "五、儿童发展", "blocks": [{"text": "待实施方案按目标写观察重点。"}]},
    {"title": "六、教师反思", "blocks": [
      {"text": "待验证问题与调整预案。"},
      {"level": 2, "text": "（一）资料依据与设计借鉴"},
      {"text": "年龄依据：此处填写实际核对的文件、年龄段与相关目标。"},
      {"text": "案例借鉴：此处填写案例名称、实际借鉴及改编范围。", "url": "https://example.com"}
    ]}
  ]
}
```

脚本从 `course-structure.json` 读取六部分顺序，要求第三部分恰好一个 `roadmap`，每格包含 `title` 和非空 `activities`。它检查结构但不替代内容判断；脉络与活动的实际对应由内容评审确认。辅助表使用 `table`，各行二列或三列且列数一致。长过程写为正文段落，不为排版全部表格化。
只加载本技能目录内的固定版本 docx 库，不回退到原电脑工具目录。
生成器统一清除三级标题开头“数字＋点号”后的空白，独立 XML 检查器复核该格式。正文、目标条目、链接及标题内部正常空格不作全局替换；原始输入文件不被改写。

可选排版字段：`titleLines` 为标题分行数组，拼接须等于 `title`，例如把主标题与副标题分开，所有行仍为小二（１８磅）、不加粗、居中；section 或文字／标题 block 可加 `pageBreakBefore: true`。通过标题起页带动后续表格，不在表格前插入空白段落。按实际篇幅安排分页，不强制每个活动一页，不为凑页数缩字。
段落 `text` 不接受换行；多个正文段落写为多个 block，辅助表单元格多段落使用字符串数组。脉络保持一行四格，不拆行；过长时缩短活动名称，将解释放正文。辅助表整行过长时拆成数个有意义的内容行。超长标题分行与段落分页由模型结合渲染结果调整，不声称脚本自动解决所有版面问题。

检查脚本先核对 DOCX XML 的字体、字号、加粗、行距、缩进、六部分、横向四格及辅助表格式，再用独立 LibreOffice 配置生成新的 PDF，核对文字完整性、页面边界和实际字体，输出每页 PNG、总览和 check-report.json。若只运行 `--xml-only`，不能声称完成 PDF 核查。Windows 已有 Word 时也可另用 Word 原生导出，再渲染 PDF 逐页核查；必须明确渲染工具和检查范围，不把替代路径写成内置 LibreOffice 检查通过。
随后查看本次报告 `image_directory` 下的页面图片，逐页目视检查表格溢出、孤立末行、标题分行、空白和字体；另查文末是否有清晰标题与分类段落、长段是否混装多类信息、标题是否与后文分离，不能只看有没有越界。每次使用独立图片目录，避免误看旧稿余页。自动报告始终保留“待人工目视”状态，不能将程序通过等同于视觉通过。分别报告内容审阅、XML 格式检查和逐页视觉检查的实际完成情况；未渲染目视时不得笼统称“排版通过”。修改后重新生成检查当前文件；缺字体或渲染工具时如实说明缺项。最终交付可编辑 docx，PDF可供预览。
